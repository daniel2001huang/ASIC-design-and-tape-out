# Lab 1 — Microwatt CPU Configuration, Verification, and Synthesis

This lab establishes the initial Microwatt CPU design for the ASIC implementation project. It covers VHDL compilation, top-level configuration, multiplier simulation, and logic synthesis using GHDL and Yosys.

The course manual identifies this exercise as **ECEN 689 Lab 8**; it is organized here as **Project Lab 1**.

## 1. Workflow

1. **Set up the environment**  
   Load the course tool environment on the Olympus cluster.

2. **Compile the CPU**  
   Import the Microwatt VHDL sources and compile the `core` entity using GHDL.

3. **Configure the top-level design**  
   Create `microwatt_top.vhdl` from the course-provided skeleton, configure the FPU and cache parameters, and verify that the top-level design compiles.

4. **Verify the multiplier**  
   Run the course-provided multiplier testbench and check that all seven directed test vectors pass.

5. **Run logic synthesis**  
   Use Yosys with the GHDL plugin to synthesize the configured CPU and map it to SKY130 standard cells.

6. **Check the cell area**  
   Extract the synthesized cell area from the synthesis log and compare it with the **5,800,000 µm²** limit.

7. **Document and package the results**  
   Record the tool outputs, complete individual reports, and generate the team submission archive.

## 2. Files and Output Locations

All paths below are relative to the project root, `ecen689_lab8/`.

| Step | File or output | Location | How it is produced |
|---|---|---|---|
| CPU compilation | `work-obj08.cf` | `microwatt_src/` | Generated by GHDL as its VHDL library database. |
| Top-level configuration | `microwatt_top.vhdl` | `microwatt_src/` | Copied from the course skeleton and edited to configure the CPU. |
| Multiplier verification | `multiply_tb_course.vhdl` | `microwatt_src/` | Copied from the course kit as the simulation testbench. |
| Compilation and simulation results | Return codes and test results | Terminal; manually recorded in `Team Lab 1/answers.txt` | Printed by the commands and testbench. |
| Batch synthesis | `synth_core_<job_id>.log` | Project root | Generated by the Slurm synthesis job. |
| Fallback synthesis | `synth_core_tmux.log` | Project root | Generated when the login-node fallback script is used. |
| Synthesis setup | `synth_<username>.ys` | `/tmp/` on the cluster | Generated from `synth_core.ys.in` by the synthesis launcher. |
| Result recording | `answers.txt` | `Team Lab 1/` | Manually updated with compilation, simulation, configuration, and area results. |
| Individual report | `<name>.md` | `reports/` | Created from the report template and completed by each member. |
| Submission staging | `lab8_team<N>_submission/` | Project root | Created by the packaging script to collect the required deliverables. |
| Submission archive | `lab8_team<N>_submission.zip` | Project root | Generated by the packaging script. |

The synthesis log contains the cell-area statistics. The supplied synthesis script does not export a standalone gate-level netlist. This lab also does not generate a GDSII layout or simulation waveform file.

## 3. Path Convention

The original course kit uses `lab8/` for the lab scripts and templates. In this repository, that folder is named `Team Lab 1/`.

The supplied scripts still reference `lab8/`. To reproduce the original workflow, restore that directory name or update the affected paths in the scripts before running them.

The `reports/` directory must also exist before saving individual reports and packaging the submission.
